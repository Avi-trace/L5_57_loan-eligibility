# Lab 5: Issues found in `loan_calculator.py`

Line numbers refer to the **original** file. Baseline: Pylint 5.17/10, Flake8 22 messages, Bandit 8 findings (2 High, 1 Medium, 5 Low).
After fixes: Pylint 10.00/10, Flake8 0, Bandit 0.

Rows 1-7 are things the tools did **not** flag. I found them by reading the demo output and checking it by hand.

| **Issue** | **Type** | **Line(s)** | **Description** | **Fix Approach** |
| --------- | -------- | ----------- | --------------- | ---------------- |
| 1. Eligibility shortcut skips the mandatory rules | Logic bug (High) - no tool flags it | 24-25 | `if credit_score > 750 or income > 25000: return True` returns before the FOIR and loan-type checks run. The demo approved an applicant with FOIR 0.8 (limit 0.5), and approved the unsupported loan type `"crypto"`. | Made every rule mandatory: age band, supported loan type, valid score, income > 0, then FOIR. Both demo cases now return `False`. |
| 2. Interest-rate unit mismatch in EMI | Logic bug (High) - no tool flags it | 14-18, 95 | `calculate_emi` divides the rate by 12 as if it were a fraction, but `main` passes `9` for 9 %. That gives a monthly rate of 75 %, and the demo printed an EMI of 375,000 for a 5 L loan (true EMI is 10,379.18). Other calls use `0.09`, so the module is inconsistent. | One convention, documented in the module docstring: the rate is a decimal fraction. `_tenure_in_months` rejects rates outside 0 to <1, so passing `9` raises `ValueError` instead of giving a silent wrong answer. |
| 3. `maxLoanAmount` ignores interest | Logic bug (High) - Pylint only sees the symptom (W0613, W0622, W0612) | 33-38 | The loop adds `available` once per month, so max loan = EMI x months. That treats the loan as interest-free, and `annual_rate` is never used. The demo gave 900,000. The true figure is about 722,600. A bank would over-lend by about 25 %. | Replaced the loop with the present value of an annuity, `available * (g - 1) / (r * g)` where `g = (1 + r)^n`, with a zero-rate branch. Renamed the shadowed `sum`. |
| 4. Insecure deserialisation with `marshal` | Security - Bandit B302 (Medium) | 4, 53-65 | `marshal.loads` on a file can run attacker-controlled data, and `marshal` is not meant for untrusted input. Its format is also Python-version specific, so records can become unreadable after an upgrade. | Switched persistence to JSON (`json.load` / `json.dump`, file `loans.json`). It is safe, readable and portable. |
| 5. FTP sends data and credentials in cleartext | Security - Bandit B402 + B321 (High) | 3, 68 | Plain FTP exposes the bureau login and the customer report on the network. | Use explicit FTPS (`FTP_TLS` plus `prot_p()` to encrypt the data channel) inside a `with` block. SFTP would be better still but needs a third-party library. Bandit blacklists the whole `ftplib` module, so the import carries `# nosec B402` with the reason. |
| 6. Hardcoded password in source | Security - Bandit B107 (Low by Bandit; serious in practice) | 67 | `password="Bureau#2024"` is committed with the code, so anyone with the repo has the credential. | Removed the defaults. Credentials are read from the `BUREAU_USER` and `BUREAU_PASSWORD` environment variables. |
| 7. `interestSaved` overstates the saving | Logic bug (Medium) - no tool flags it | 76-79 | It subtracts total payments, but the difference includes the prepaid principal. The demo printed 62,275, but the true interest saved is 12,275 (62,275 - 50,000). | Subtract the prepayment from the difference. Validate `0 <= prepayment <= principal`. Handle the full-prepayment case, which would otherwise divide by zero. |
| 8. Risk band accepts impossible scores | Logic bug (Medium) - no tool flags it | 81-90 | A score of 950 returned `"LOW"`. Scores run 300-900, but only the lower bound was checked. | Check `300 <= score <= 900` first and return `"INVALID"` otherwise. The bands are unchanged. |
| 9. Loan book is overwritten on every run | Logic bug / data loss (Medium) - no tool flags it | 53-58 | `applications` starts empty in each process and `saveApplication` writes the whole dict, so earlier records are wiped. Two runs left 1 record, not 2. | `save_application` loads the existing file first. |
| 10. Mutable default argument | Pylint W0102 (Medium) | 20-21 | `history=[]` is shared across all calls. It grows forever (a memory leak) and nothing ever reads it. | Removed the parameter. This also fixes Pylint R0913 and R0917 (too many arguments). |
| 11. Demo runs on import | Design (Medium) - Flake8 E305 only hints at it | 106 | `main()` is called at module level, so `import loan_calculator` runs the demo and writes `loans.bin` as a side effect. The module cannot be unit tested. | Added `if __name__ == "__main__":`. The demo uses a temporary folder, so repeated runs give the same output. |
| 12. Division by zero and missing input validation | Robustness (Medium) - no tool flags it | 16-18, 26 | A 0 % rate divides by zero in the EMI formula. `existing_emi / income` fails when income is 0. Negative or zero principal and tenure are accepted. | Added a zero-rate branch, an `income <= 0` guard, and `ValueError` checks for principal, rate and years. |
| 13. Unsafe `subprocess` call to `mail` | Security - Bandit B404, B603, B607 (Low); Pylint W1510 | 6, 73-74 | Runs an external program found through `PATH`, with the applicant's e-mail address as an argument. An address starting with `-` could be read as an option. The return code is never checked. | Replaced it with `smtplib` and `EmailMessage`, which also rejects header-injection characters. `subprocess` is no longer imported. |
| 14. Weak random number generator for application IDs | Security - Bandit B311 (Low) | 5, 50-51 | `random` is predictable, and two applications can get the same ID and silently overwrite each other. | Use `secrets.randbelow`, and loop until the ID is not already in the loan book. |
| 15. Files and connections not closed safely | Quality - Pylint R1732 (x3) | 55-58, 63-65, 70 | `open()` without `with` leaks the handle if an exception occurs. In `uploadToBureau` the file is never closed at all. | All file and FTP access now uses `with`, and files are opened with `encoding="utf-8"`. |
| 16. Style and naming | Style - Pylint C0103 x11, C0114, C0116 x12, C0325, R1705, R1714, R1703, W0603, W0611, W1309; Flake8 E302, E501, F401, F541 | 2, 14-106 (throughout) | camelCase function names, no docstrings, long lines, 1 blank line between functions, unused `import math`, an f-string with no placeholders (L104), redundant parentheses (L79), `else` after `return`, a chain of `==` instead of `in`, and a `global` statement. | Renamed to snake_case, added docstrings, wrapped lines to 79 characters, removed the unused import and f-string, simplified the return logic, and replaced `global` with `clear()` / `update()` on the shared dict. |
